# GenAI governance lab: limits of the test methodology

These are limits of how the lab tests, not of any configuration. The
[configuration notes](configuration-notes.md) describe how settings change what the lab observes.
The [manual steps](manual-steps.md) are tests, with evidence recorded alongside automated results.

| # | Methodology limit | How the lab handles it |
|---|---|---|
| 1 | **Where inference runs isn't logged.** No system table records which country or model processed a Genie request. | P-06 and M-01 record configuration; P-07 and D-05 probe feature availability. Only a refusal that names Geography or cross-Geo processing establishes the enforcement reason in P-07; a region-unavailable response is INFO. For in-country previews, account-team confirmation is workspace-specific. |
| 2 | **Account-level controls aren't bundle resources** (Geography enforcement, partner-powered AI enforcement, budgets, ingress, the Genie One switch and account groups). | `scripts/account_checks.py` inventories readable settings using an account profile: partner-powered AI and its enforce flag, CSP/ESM defaults, Geography settings, serverless network policies and budgets. M-01, M-02 and M-06 cover the account-console checks, including ingress and the Genie One switch, which the script doesn't read. |
| 3 | **Test identities are managed outside the bundle.** An organization's personas come from its identity provider (IdP); the lab doesn't provision its real users or role memberships. | `scripts/bootstrap_personas.sh` can create sandbox service principals and account groups, or the identity team can supply them. Teardown can remove the identities recorded by bootstrap. |
| 4 | **Genie answers vary.** | The tests compare returned data (exact masked values, facility sets and NRIC patterns), not wording, with one retry. Empty or failed answers don't count as evidence that the control worked. |
| 5 | **System table results can lag by hours and access requires grants.** | The separate `lab_evidence` job can run the next day; the [README](../README.md) lists the access prerequisite. See also row 12 for how the job handles missing evidence. |
| 6 | **Network controls can block the test itself.** Private Link, IP access lists or egress rules can prevent CLI or notebook API calls. | `scripts/run_audit.sh` starts with a connectivity preflight; the [README](../README.md) lists network prerequisites. |
| 7 | **The bundle can't create the lab's Genie Agent and its backing tables in the same deployment.** The Genie API needs the tables to exist first. | The setup job creates the agent with the SDK after the tables exist. [`optional/clinic.genie_space.yml.example`](../optional/clinic.genie_space.yml.example) shows the bundle-managed option after the first run. |
| 8 | **The lab reuses existing endpoints** for vector search, agents and Knowledge Assistant instead of provisioning them for each run. | Setup adds a lab-group ACL entry only where the group had none and records it in `lab_manifest`. Teardown removes those entries and preserves the rest of the current ACL. R-01 reads the Knowledge Assistant without changing it; invocation is opt-in. |
| 9 | **The bundle schema doesn't list `CREATE_SERVICE`.** CLI 1.20 rejects it in `grants` under `bundle validate --strict`. | `17_genai_setup` grants it in SQL. A deployment that changes the tools schema's grants resets them; running `lab_setup` again reapplies the lab grant. |
| 10 | **A denial can come from an unrelated prerequisite**, such as missing `USE CATALOG`, an expired token, a missing entitlement or another table. | The test checks the denial clause for both the privilege and the exact securable, ignoring stack traces. A generic 403, such as a B-04 response without the privilege or connection, is SKIP. Self-tests: `python3 src/lib/test_checks.py`. |
| 11 | **Shared write access would let personas alter one another's results.** | Each persona writes only to its own `test_results_<persona>` staging table. The trusted collector, `lab_collect`, runs as the deployer and copies only rows whose `persona` matches the source table into `test_results`. |
| 12 | **Evidence arrives asynchronously.** | `lab_evidence` correlates audit, usage and inference records by suite window, workspace, lab Genie Agent or model service, persona and request (e.g. `genieStartConversationMessage` or the G-01 prompt). The sandbox evidence check reports missing rows as PENDING within `log_latency_hours` (24 h by default), then FAIL if they're still missing. |
| 13 | **B-06 only sees grants visible to the audit identity.** | Without metastore-admin visibility, the inventory cannot establish the absence of grants. An incomplete list can still show a grant; it cannot establish that the list is exhaustive. |
| 14 | **Ownership of an existing ACL entry, grant or object isn't always attributable to the lab.** | Setup records an ACL entry or `USE CATALOG` grant only if it was absent before and present after. Teardown removes recorded entries and lists unattributed grants and legacy probe objects for manual review. |
| 15 | **Probe objects can outlive an interrupted run.** | The persona writes an intent row to its `probe_log_<persona>` before a B-probe create. The collector adds anything not verified deleted to the manifest by exact per-run name; teardown deletes it and checks for HTTP 404. |
