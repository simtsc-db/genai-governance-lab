# GenAI governance lab: limits of this approach, and how each is covered

The lab proves controls by **configuration** and by **observed behaviour** under test identities.
Some things it can't prove on its own. Each gap below says how the runbook covers it.

| # | Gap | How it's covered |
|---|---|---|
| 1 | **Where inference runs isn't logged.** No system table records which country or model processed a Genie request. | Configuration evidence (region, in-Geo enforcement, M-01) plus a negative test: features that need cross-Geo are refused (P-07, D-05). P-07 passes only if the refusal names Geography / cross-Geo processing; a plain "not available in this region" is INFO. In-country preview enrolment is confirmed per workspace by the account team. |
| 2 | **The Compliance Security Profile changes behaviour.** With CSP on, `ai_mask` 2.0 isn't available, RBAC is off by default and some features differ. The reference configuration has CSP off. | The audit records the CSP state (P-08), and tests that depend on it switch their expectation (D-07 becomes SKIP "CSP"). If you turn CSP on later, rerun the lab, because enabling CSP can't be undone and changes some results. |
| 3 | **Account-level controls aren't bundle resources** (Geography enforcement, partner-powered AI enforcement, budgets, ingress, Genie One switch, account groups). | `scripts/account_checks.py` is a read-only **inventory** with an account profile: partner-powered AI (account value and enforce), CSP/ESM defaults, geo-related account settings, serverless network policies and budgets (listed, not judged). It does **not** read context-based ingress or the Genie One switch; those are manual steps M-02 and M-06, as is M-01. |
| 4 | **Some controls are UI-only** (Previews toggles, service policy attachment, Data Classification). | Manual steps with a scripted before/after check (M-03, M-04). |
| 5 | **Identities come from your IdP.** Service principals and groups aren't bundle resources. | `scripts/bootstrap_personas.sh` creates lab-only service principals and account groups; your identity team can create them instead. Teardown removes them. |
| 6 | **Service principals aren't real clinicians.** Some user-only features (mobile app, Slack/Teams, file upload UI) can't be exercised by a service principal. | UI checks in the runbook with a real test user (4.1, 4.3, M-07). |
| 7 | **Genie answers aren't deterministic.** | Tests assert on the returned **data** (exact masked values, exact facility set, NRIC pattern), not on wording, with one retry. An empty or failed answer is never a PASS. |
| 8 | **Agent mode may be disabled** on a workspace. | Probes use chat mode; agent mode is a UI step (A-05) and is skipped where it is off. |
| 9 | **System tables arrive with a delay of hours** and need grants. | Separate `lab_evidence` job, run the next day; prerequisite in the README. |
| 10 | **Preview parity.** The workspace the lab was developed on may have more previews enabled than yours. | Each Beta test checks its prerequisite and reports SKIP with the reason instead of FAIL. |
| 11 | **Status drift.** Beta and Preview features change quickly. | The [controls matrix](controls-matrix.md) is dated and links every control to its doc page. |
| 12 | **Network.** Private Link, IP access lists or egress rules can block the CLI or notebook API calls. | `run_audit.sh` starts with a connectivity preflight; README lists the network prerequisite. |
| 13 | **Genie Agent as a bundle resource.** Genie refuses to create an agent whose tables don't exist yet, so a single deploy can't create both. | The setup job creates the agent with the SDK. `optional/clinic.genie_space.yml.example` switches to bundle-managed after the first run. |
| 14 | **Cost.** Genie usage by service principals is billed. | The suite asks about a dozen questions per run; README explains the cost. |
| 15 | **NRIC / FIN in prompts vs at rest.** The built-in sensitive-data guardrail (service policies) has **no Singapore class** for prompts. At rest, automatic Data Classification **does** detect NRIC, FIN and work permit numbers (`class.sg_nric`, `class.sg_fin`, `class.sg_work_permit_number`, SG-region workspaces only), and one ABAC policy then masks every tagged column. But in the Asia Geo Data Classification needs cross-Geo processing, so with in-Geo enforcement on it is unavailable. | At rest: the ABAC policy `lab_mask_sg_identifiers` plus D-08 (every tagged column covered). Where classification is unavailable, the documented fallback is to apply the same `class.sg_*` tags by hand; the lab does this on one column of `sg_identifiers_simulated` and labels it SIMULATED. Prompts: an LLM-as-a-judge custom guardrail is still needed (M-04). Unity Catalog masks remain the primary control. |
| 16 | **Custom guardrails: SQL functions can't use regex; Python functions don't run with restricted serverless egress** (and then deny everything). | LLM-as-a-judge guardrail; Python policy shipped for workspaces without egress restrictions. |
| 17 | **Schema-level EXECUTE also opens every model service in that schema.** Without care, outsiders can call `lab_chat` through a schema-level grant. | The lab grants only USE SCHEMA at schema level and EXECUTE on the service itself. Check your schema grants. |
| 18 | **AI Functions permissions are open by default** (all users have EXECUTE on `system.ai`); restricting them needs the feature enabled by the account team. | F-01 records the state; F-02 shows the stronger control: AI Functions only receive what UC lets the caller read. |
| 19 | **`ai_query` doesn't support model services you create yet.** Per the Unity Gateway docs, `ai_query` support is only for Databricks-provided models; the workspace reports it as "ai_query through UC Model Services is not enabled". Also, only usage tracking applies to `ai_query` batch workloads (no rate limits, guardrails or inference tables). | F-03 records INFO "not supported for this route"; the gateway API path (G-01 … G-03) is tested instead. |
| 20 | **Existing endpoints are reused** (vector search, agent, Knowledge Assistant) instead of deployed, to save time and cost. | Setup adds an ACL entry for a lab group only where the group had none, and records it in `lab_manifest`; teardown removes exactly those entries and keeps the rest of the ACL as it is at teardown time. The Knowledge Assistant is only read (R-01), never changed. |
| 21 | **The bundle schema doesn't list `CREATE_SERVICE` yet** (CLI 1.20), so `bundle validate --strict` rejects it in `grants`. | `17_genai_setup` grants it in SQL. Rerun `lab_setup` after a deploy that changes the tools schema's grants, because the bundle resets them. |
| 22 | **A classic serving endpoint with an external model is a route outside Unity Gateway** (B-05). With the workspace setting *Enforce Unity Gateway* off, any user with *Workspace access* can create one, pointing at any URL with their own key; no grant stops it. | **Partly mitigated by Enforce Unity Gateway** (Settings > Advanced; B-08 reads it, M-14): `databricks-*` pay-per-token endpoints are disabled and **new** external-model and provisioned-throughput serving endpoints can't be created outside Unity Gateway, and B-05 then PASSes only on the error that names the probe endpoint and the enforcement. Caveats ([migration guide](https://docs.databricks.com/aws/en/ai-gateway/migrate-to-unity-gateway)): existing endpoints stay queryable, so B-08 PASS doesn't close them: **B-09** inventories them. B-08 PASS + B-09 PASS (workspace admin, complete classification) = no existing legacy external-model or provisioned-throughput route right now; historical usage is a separate manual review. Caveats: the endpoint list only shows what the caller can see (B-09 is MANUAL for a non-admin), and B-09's usage history only covers endpoints with [usage tracking](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints) on, so it is supplementary; and the setting is offered only in workspaces with legacy AI Gateway endpoints (otherwise ask the account team). Defence in depth: restricted serverless egress (M-02) also covers Model Serving endpoints that call external models; alert on `createServingEndpoint` in case the setting is turned off. |
| 23 | **`system.ai` grants EXECUTE to all users by default** (B-07), so everyone can use every Databricks-provided model and MCP. | Revoke from `account users` and grant per group after a metastore admin takes `MANAGE` on `system.ai` (M-13). |
| 24 | **Denials must match the target.** A permission error can come from something else (missing USE CATALOG, an expired token, a missing entitlement, another table). | A denial counts only if the error's denial clause names both the privilege under test and the exact securable (e.g. `does not have SELECT on Table <target>`, the Genie space ID, the full service name); stack traces are ignored. Anything else, including a generic 403 (seen for B-04's MCP service create), is SKIP. Self-tests: `python3 src/lib/test_checks.py`. |
| 25 | **Results integrity.** Personas could otherwise write each other's results. | Each persona writes only its own staging table; `lab_collect` (deployer) merges rows whose persona matches the table. |
| 26 | **Evidence timing.** Audit logs, gateway usage and inference tables arrive late. | `lab_evidence` correlates by suite run window, workspace, the lab's Genie Agent / model service, persona and the actual request (`genieStartConversationMessage`, the G-01 prompt). Missing rows are PENDING while the run is younger than `log_latency_hours` (24 h), FAIL after. |
| 27 | **B-06 visibility.** `information_schema` shows only the grants the caller can see. | B-06 is MANUAL (inconclusive) unless the audit runs as a metastore admin; grants to anyone outside `approved_builders` are FAIL. |
| 28 | **Ownership of reused objects.** The lab can't prove it added an ACL entry or grant that already existed, or created a fixed-name object from an earlier version. | Setup records an ACL entry or `USE CATALOG` grant only if it was absent before and present after; teardown removes only those and lists other lab-group entries and legacy probe objects for manual removal. |
| 29 | **Probe objects can outlive a crash.** | Each persona writes an intent row to its own `probe_log_<persona>` before every B-probe create; the collector turns anything not verified deleted into a manifest item (exact per-run name only) and teardown deletes it and verifies GET → 404. |
| 30 | **Enforce Unity Gateway switches off what still runs on legacy endpoints.** Per the [migration guide](https://docs.databricks.com/aws/en/ai-gateway/migrate-to-unity-gateway): `databricks-*` pay-per-token endpoints are disabled, AI Search endpoints can't be created through Unity Gateway yet, Knowledge Assistant and Multi-Agent Supervisor agents that depend on AI Search don't work, `ai_query` supports only `system.ai` model services, custom agents on model serving endpoints can't use authentication passthrough, and (per the [KB migration guide](https://kb.databricks.com/unity-catalog/migration-guide-moving-to-unity-ai-gateway)) Databricks Apps using a serving endpoint resource stop working until the app code queries a model service and the app's service principal has `EXECUTE` on it. Expect, in a test workspace with the setting on: a vector index with embeddings on a `databricks-*` endpoint fails to query, an existing agent endpoint that calls a `databricks-*` chat endpoint fails, and `ai_query` on a `databricks-*` endpoint name fails. | V-01, V-02, S-01 and F-02 record SKIP instead of a verdict: S-01 and F-02 say the legacy endpoint they rely on is disabled by the workspace's Enforce Unity Gateway setting; V-01 and V-02 carry the setup error (permission denied on the `databricks-*` embedding endpoint); the Unity Gateway tests (G-01 … G-04, B-01 … B-04b, T-01, T-02) are unaffected. Migrate those workloads before enabling the setting on a customer workspace; B-09 lists the other AI endpoints as INFO, with recent `databricks-*` traffic as supplementary evidence. R-01 records configuration only and doesn't invoke the Knowledge Assistant, so it doesn't show this. |
